# L1轻量级交付

## 一、任务目标

针对L1级简单需求，将产品需求、技术设计和验证要点合并为一份轻量级交付契约，定稿后直接开展代码开发、自我审查及功能验证，最终交付可运行的代码。

跳过前后端独立交付和独立审查环节，由同一AI Agent在同一对话窗口中完成全部工作。

## 二、执行前提

当前工作环境必须是具备本地项目文件读取、目录遍历和文件修改能力的AI Agent。

执行前检查：

1. 确认当前工作目录为项目根目录。
2. 开发者已提供完整的需求描述（含原型图等资料）。
3. 已充分沟通并确认需求细节，不存在未解决的歧义。

如果缺少必要信息或存在待确认事项，必须停止并向开发者说明。

### 前置分析反问

开始执行前，AI必须先完成以下步骤：

1. **资料分析**：仔细阅读本Skill要求读取的全部资料，包括项目上下文、相关契约及实际代码，全面理解本次任务的范围、目标和约束。
2. **识别不确定点**：基于资料分析，主动识别以下类型的问题：
   - 资料之间存在矛盾、冲突或不一致的地方。
   - 契约、代码或文档中存在模糊、遗漏或无法确认的内容。
   - 本Skill的流程、标准或要求与当前项目实际情况可能存在不匹配的地方。
   - 开发者可能尚未明确说明，但对本次任务执行有实质性影响的约束、例外或特殊要求。
3. **列举并提问**：将识别出的不确定点整理为具体问题，向开发者提问。提问应聚焦影响任务正确性的关键问题，避免重复询问已经明确的信息。
4. **确认后执行**：开发者解答后，AI以解答为准开展后续工作。如经分析后不存在不确定点，可直接开始执行。

## 三、轻量级契约编写

### 3.1 需求理解

阅读开发者提供的需求描述，理解：

- 需求背景及业务目标。
- 核心功能及操作场景。
- 用户角色及权限关系。
- 业务规则及约束条件。
- 与现有业务的关联关系。

### 3.2 主动反问

基于需求理解，主动向开发者提问：

- 需求描述中不明确或存在歧义的地方。
- 边界条件、异常场景及极端情况。
- 与现有业务可能存在的冲突或影响。

提问应聚焦业务层面，不涉及技术实现方案。

### 3.3 简化技术设计

在编码前输出简化的技术设计思路，包括：

- 涉及的模块、页面或接口。
- 数据变更（如有）。
- 关键实现逻辑。

供开发者快速确认。技术设计确认后，方可进入契约编写。

### 3.4 契约内容

轻量级交付契约合并产品需求、技术设计和验证要点，统一存放在项目根目录下的交付契约目录中：

```text
交付契约/
└── <需求名称>/
    └── v1/
        └── 1.轻量级契约.md
```

应包含：

**需求摘要**

- 需求背景与目标。
- 核心功能及操作场景。
- 用户角色及权限。

**业务规则**

- 关键业务规则及约束。
- 边界条件及异常处理。

**技术方案**

- 涉及的模块、页面、接口。
- 数据模型变更（如有）。
- 关键实现逻辑。

**验证要点**

- 核心功能的验证方式。
- 关键业务规则的验证方式。
- 边界条件的验证方式。

**需求范围**

- 明确包含的功能。
- 明确不包含的内容。

### 3.5 契约定稿

契约编写完成后，提交给开发者审核。开发者确认后，契约正式定稿，方可开始代码开发。

## 四、代码开发

### 4.1 开发约束

- 严格遵循已定稿的轻量级交付契约，不得擅自扩大需求范围。
- 遵循项目编码规范和架构约束。
- 如需调整周边代码，必须先向开发者说明影响范围并获得确认。

### 4.2 变更范围控制

- 开发范围严格限定在需求范围内。
- 不得随意修改与本次需求无关的代码。

## 五、代码审查

### 5.1 自我审查

代码开发完成后，进行自我审查，检查：

- 代码是否符合项目编码规范。
- 业务逻辑是否正确。
- 是否存在潜在的安全风险。
- 是否引入了回归风险。

### 5.2 问题报告

审查发现问题后，不直接修复，输出问题清单，包括：

- 问题描述。
- 问题位置。
- 修复建议。

由开发者决定是否需要修复及如何修复。

## 六、功能验证

开发者根据轻量级交付契约中的验证要点进行测试：

- 核心功能是否正常工作。
- 关键业务规则是否正确执行。
- 边界条件是否正确处理。

开发者测试通过即可，不需要编写自动化测试。

## 七、执行约束

1. 必须在轻量级交付契约定稿后才能开始代码开发。
2. 开发范围严格限定在需求范围内，不得擅自扩大。
3. 如需调整周边代码，必须先获得开发者确认。
4. 代码审查发现问题后，不直接修复，输出问题清单由开发者决定。
5. 不进行独立审查，由开发者审核契约和验收代码。
6. 不需要编写自动化测试，以开发者功能验证为准。
7. 输出结果包含定稿的轻量级交付契约和可运行的代码。

## 八、完成标准

同时满足以下条件，才算完成：

- [ ] 已完成轻量级交付契约编写并定稿。
- [ ] 已按照契约完成代码开发。
- [ ] 已完成自我代码审查。
- [ ] 已向开发者输出审查问题清单（如有）。
- [ ] 开发者已完成功能验证并测试通过。
- [ ] 开发者已确认最终交付结果。

完成后，向开发者说明交付摘要及代码变更位置。
