# 后端交付成果独立审查

## 一、任务目标

以独立审查者的视角，对本次需求后端开发及接口自动化测试完成后的交付成果进行全面审查。

重点评估代码质量、业务逻辑正确性、架构一致性、潜在回归风险及交付契约符合度，识别代码缺陷、设计偏差及与契约不一致的问题，输出结构化审查报告。

本Skill只负责审查发现问题和输出报告，不直接修改任何代码文件，也不执行自动化测试或数据库操作。

## 二、执行前提

必须使用全新的AI Agent会话执行审查，不得沿用开发或测试阶段的对话上下文，避免自我审查偏差。

必须读取以下文件：

1. 项目根目录下的"项目上下文.md"
2. 本次需求的1.产品契约.md
3. 本次需求的2.后端技术契约.md
4. 本次需求的3.后端测试契约.md

同时阅读本次需求涉及的实际后端代码，包括业务代码和测试代码。

同时获取后端接口自动化测试结果。

如果缺少必要文件、契约尚未定稿、后端代码开发或自动化测试尚未完成，必须停止审查并向开发者说明原因，不得自行假设。

### 前置分析反问

开始执行前，AI必须先完成以下步骤：

1. **资料分析**：仔细阅读本Skill要求读取的全部资料，包括项目上下文、相关契约及实际代码，全面理解本次任务的范围、目标和约束。
2. **识别不确定点**：基于资料分析，主动识别以下类型的问题：
   - 资料之间存在矛盾、冲突或不一致的地方。
   - 契约、代码或文档中存在模糊、遗漏或无法确认的内容。
   - 本Skill的流程、标准或要求与当前项目实际情况可能存在不匹配的地方。
   - 开发者可能尚未明确说明，但对本次任务执行有实质性影响的约束、例外或特殊要求。
3. **列举并提问**：将识别出的不确定点整理为具体问题，向开发者提问。提问应聚焦影响任务正确性的关键问题，避免重复询问已经明确的信息。
4. **确认后执行**：开发者解答后，AI以解答为准开展后续工作。如经分析后不存在不确定点，可直接开始执行。

## 三、交付成果审查

### 3.1 代码质量审查

检查代码是否符合项目编码规范，重点关注：

- 命名规范：包名、文件、变量、函数、结构体、接口、常量及数据库表和字段的命名。
- 代码风格：缩进、换行、注释、导包顺序、错误处理及日志打印。
- 代码结构：目录和文件组织方式、模块职责及函数设计。
- 可读性：注释质量、代码复杂度及职责清晰度。
- 重复代码：是否存在可复用但未复用的公共组件或重复实现。

### 3.2 业务逻辑正确性审查

结合产品契约，检查业务逻辑实现是否正确：

- 业务规则是否在产品契约中有对应实现。
- 业务流程是否覆盖正常、异常和边界场景。
- 状态流转及数据变化是否符合业务要求。
- 是否存在业务规则遗漏、实现偏差或错误处理缺失。

### 3.3 架构一致性审查

结合架构设计，检查代码是否符合项目既定架构：

- 是否遵循分层架构及模块职责划分，是否存在跨层调用。
- 是否正确使用公共组件及工具函数。
- 模块职责是否清晰，调用关系是否合理。
- 是否引入与项目技术栈不一致的依赖。

### 3.4 接口实现审查

结合后端技术契约，检查接口实现是否符合约定：

- 接口路径、请求方法是否正确。
- 请求参数及响应结构是否符合约定。
- 错误码定义及返回是否符合规范。
- 参数校验是否完整，是否覆盖必填、类型、范围等约束。
- 接口实现是否满足产品契约中的业务需求。

### 3.5 数据库操作审查

检查数据库相关代码：

- 数据模型及数据库访问方式是否正确。
- 事务处理是否恰当，事务边界是否合理。
- 索引使用是否合理，是否存在性能隐患。
- 并发安全性及数据一致性保障。
- 是否存在SQL注入等安全风险。

### 3.6 错误处理、日志与权限审查

- 错误处理是否符合规范：错误封装方式、日志记录与错误返回的分离原则。
- 日志打印是否规范，是否记录必要上下文。
- 身份认证及权限控制是否正确实现。
- 敏感信息处理、输入校验及安全防护是否符合安全规范。

### 3.7 回归风险评估

评估本次变更对既有功能的影响：

- 是否修改了共享模块、公共工具类或通用数据库查询逻辑。
- 变更是否可能连带影响其他已有接口或功能。
- 是否存在因修复当前问题而破坏其他模块的隐性回归风险。

### 3.8 测试代码审查

结合后端测试契约，检查测试代码：

- 测试代码质量、组织方式及命名规范。
- 测试用例是否覆盖核心业务场景、异常场景及边界条件。
- 测试代码是否符合项目测试规范及编码规范。
- 测试用例与后端测试契约的对应关系是否清晰可追溯。
- 业务代码的可测试性，以及测试用例对业务代码的覆盖情况。

### 3.9 代码与契约一致性审查

检查代码实现与交付契约之间的一致性：

- 代码实现是否与产品契约的业务规则一致。
- 代码实现是否与后端技术契约的技术方案一致。
- 接口定义、数据结构、数据库设计是否与契约一致。
- 测试代码是否与后端测试契约一致。

### 3.10 需求追溯审查

建立以下需求追溯关系：

产品需求 → 代码实现 → 测试用例

逐项检查：

- 每项核心业务需求是否在代码中有对应实现。
- 每处代码实现是否有对应的测试用例覆盖。
- 是否存在无对应实现的需求，或无对应测试的代码。

对于无法建立对应关系的内容，必须记录为审查问题。

## 四、问题分级

审查发现的问题必须按照以下等级分类：

1. P0：严重问题，影响业务正确性或存在重大风险。
2. P1：重要问题，核心需求遗漏、技术方案错误或关键逻辑缺陷。
3. P2：一般问题，局部设计不完整或存在明显问题。
4. P3：优化建议，不影响当前需求正确交付。

每个问题必须明确：

- 问题等级。
- 所属文件。
- 具体文件路径、函数/方法名、行号或相关代码片段。
- 问题描述。
- 产生的影响。
- 修改建议及原因。

不得将个人偏好或非必要优化建议判定为实际缺陷。

## 五、审查报告

审查完成后，输出结构化审查报告，包含以下内容：

### 5.1 审查结论

给出以下结论之一：

- 通过：不存在未解决的P0、P1问题，满足审查完成标准。
- 条件通过：不存在未解决的P0、P1问题，但仍有需要开发者关注的遗留问题。
- 不通过：存在未解决的P0或P1问题，不能通过审查。

### 5.2 问题清单

逐项列出审查发现的问题，包括问题等级、所属文件、具体位置、问题描述、影响及修改建议。

### 5.3 需求追溯检查

列出产品需求、代码实现及测试用例之间的对应关系，明确已覆盖内容及缺失项。

### 5.4 代码与契约一致性检查

说明代码实现与产品契约、后端技术契约及后端测试契约之间的一致性检查结果。

### 5.5 最终审查结果

汇总未解决问题、遗留风险及是否满足审查通过条件。

审查报告必须提供明确的文件路径、函数/方法名、行号或代码片段定位，不得只输出笼统的审查意见。

## 六、审核与迭代

### 6.1 独立审查

首次审查必须独立完成，不得依赖开发或测试阶段的结论或自我判断。仅通过代码阅读完成审查，不得运行静态代码分析工具、执行测试或连接数据库辅助审查。

### 6.2 开发者审核

向开发者展示审查报告及所有待处理问题，由开发者决定是否修改代码。

只输出审查意见和修改建议，不得直接修改任何业务代码或测试代码。

审查发现问题后，由开发者逐项确认，筛选出确实需要修复的问题，再交由负责后端开发的AI进行针对性修复。

如果开发者决定暂不修复某个问题，允许将其记录为遗留风险，不影响审查结论。

### 6.3 重新审查

代码修复完成后，必须重新执行完整审查，而不是只检查上一轮发现的问题。

重新审查可用之前的审查Agent执行，相关接口自动化测试由之前的测试Agent执行。

每轮审查都必须重新检查：

1. 代码质量、业务逻辑及架构一致性。
2. 代码与三份契约之间的一致性。
3. 产品需求到代码实现、测试用例的追溯关系。
4. 上一轮问题是否得到有效解决。
5. 修改是否引入新的遗漏、冲突或回归风险。

重复执行审查、报告、修复和复查，直到满足审查通过条件，并由开发者确认最终结果。

## 七、执行约束

1. 必须使用全新AI Agent会话执行首次审查。
2. 必须读取完整的项目上下文和本次需求三份契约。
3. 必须结合实际后端代码（包括业务代码和测试代码）进行审查。
4. 仅通过代码阅读完成审查，不得运行工具、执行测试或连接数据库。
5. 不得直接修改任何业务代码或测试代码。
6. 不得擅自改变已确认的业务规则和技术方案。
7. 所有问题必须分级并提供具体文件路径、函数/方法名、行号或代码片段定位。
8. 不得将未经确认的优化建议作为正式审查要求。
9. 不得推测缺失信息，无法确认的内容必须明确标记。
10. 所有问题必须有对应的代码内容或项目资料作为依据。
11. 未经开发者确认，不得宣称审查最终通过。

## 八、完成标准

同时满足以下条件，才算完成：

- [ ] 已使用全新AI Agent会话执行首次审查。
- [ ] 已读取项目根目录下的"项目上下文.md"及三份需求契约。
- [ ] 已阅读本次需求涉及的实际后端代码（业务代码和测试代码）。
- [ ] 已完成代码质量审查。
- [ ] 已完成业务逻辑正确性审查。
- [ ] 已完成架构一致性审查。
- [ ] 已完成接口实现、数据库操作、错误处理及权限审查。
- [ ] 已完成回归风险评估。
- [ ] 已完成测试代码审查。
- [ ] 已完成代码与契约一致性审查。
- [ ] 已完成需求追溯检查。
- [ ] 所有审查问题均已分级并提供具体位置。
- [ ] 已输出完整审查报告。
- [ ] 不存在未解决的P0和P1问题。
- [ ] 开发者已确认最终审查结果。

完成后，向开发者说明审查结论、遗留问题及后端独立交付是否正式完成。

审查通过后，意味着后端独立交付阶段正式完成，可以进入前端独立交付阶段。
