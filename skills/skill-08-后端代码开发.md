# 后端代码开发

## 一、任务目标

根据本次需求的产品契约、后端技术契约、项目上下文及现有后端代码，完成后端功能开发。

严格遵循已确认的业务规则、技术方案和项目编码规范，合理控制代码变更范围，确保代码实现符合需求及技术设计。

## 二、执行前提

必须读取以下文件：

1. 项目根目录下的"项目上下文.md"
2. 本次需求的1.产品契约.md
3. 本次需求的2.后端技术契约.md

本次需求的两份契约必须已经通过独立审查，并由开发者确认通过。

如果缺少必要文件、契约尚未定稿或存在影响开发的待确认事项，必须停止相关开发并向开发者反馈。

必须结合实际项目代码分析现有模块、调用链路、公共组件、数据结构及已有实现，不能仅根据契约文字直接生成代码。

### 前置分析反问

开始执行前，AI必须先完成以下步骤：

1. **资料分析**：仔细阅读本Skill要求读取的全部资料，包括项目上下文、相关契约及实际代码，全面理解本次任务的范围、目标和约束。
2. **识别不确定点**：基于资料分析，主动识别以下类型的问题：
   - 资料之间存在矛盾、冲突或不一致的地方。
   - 契约、代码或文档中存在模糊、遗漏或无法确认的内容。
   - 本Skill的流程、标准或要求与当前项目实际情况可能存在不匹配的地方。
   - 开发者可能尚未明确说明，但对本次任务执行有实质性影响的约束、例外或特殊要求。
3. **列举并提问**：将识别出的不确定点整理为具体问题，向开发者提问。提问应聚焦影响任务正确性的关键问题，避免重复询问已经明确的信息。
4. **确认后执行**：开发者解答后，AI以解答为准开展后续工作。如经分析后不存在不确定点，可直接开始执行。

## 三、开发分析

### 3.1 理解需求与技术方案

阅读产品契约和后端技术契约，明确：

- 本次需求的业务目标及业务规则。
- 涉及的后端模块及文件变更范围。
- 接口设计及数据结构。
- 核心业务逻辑及处理流程。
- 数据库变更及技术约束。
- 外部依赖及异常处理方式。

### 3.2 分析现有代码

结合项目上下文，阅读本次需求涉及的实际代码，识别：

- 项目目录结构及模块职责。
- 接口入口及调用链路。
- 现有业务逻辑及公共组件。
- 数据模型及数据库访问方式。
- 中间件、工具函数及公共服务。
- 现有代码中的可复用实现。

优先复用项目已有的公共组件、工具函数和业务模块，避免重复实现。

### 3.3 制定开发方案

根据技术契约和实际代码，明确：

- 需要新增、修改的文件。
- 各文件承担的职责。
- 核心函数及方法的实现方式。
- 模块之间的调用关系。
- 数据结构及数据库相关代码变更。
- 可能影响现有功能的修改点。

如果发现技术契约存在遗漏、冲突或无法落地的情况，必须向开发者说明，不得擅自改变已确认的技术方案。

对于技术契约未明确规定的实现细节，允许结合实际代码合理调整，但不得改变已确认的业务规则、接口约定和数据结构。

## 四、代码开发

### 4.1 开发实施

按照确认的开发方案逐步完成代码修改：

1. 根据技术契约新增或修改目标文件。
2. 实现接口及请求参数处理。
3. 实现核心业务逻辑。
4. 实现数据结构及数据库访问逻辑。
5. 实现必要的参数校验、错误处理及权限控制。
6. 完成模块之间的调用及依赖关系。
7. 检查代码变更是否符合技术契约。

开发过程中允许AI自主完成明确的开发任务，不需要每次修改都等待开发者确认。

### 4.2 代码变更管理

允许AI根据开发需要新增、修改和删除代码文件，但必须遵循以下要求：

- 所有变更必须属于本次需求范围。
- 优先采用局部修改，避免无关重构。
- 删除已有业务代码前，必须获得开发者确认。
- 进行大范围重构前，必须获得开发者确认。
- 不得擅自修改与本次需求无关的业务逻辑。
- 不得擅自引入新的技术栈或第三方依赖。

### 4.3 数据库变更

允许直接修改项目中的数据库模型、数据结构定义及相关代码。

涉及外部数据库操作时，例如创建数据表、修改表结构、创建索引或执行数据库变更，必须向开发者说明：

- 需要执行的数据库操作。
- 涉及的数据表及字段。
- 变更内容及原因。
- 必要的SQL语句或操作说明。

外部数据库操作由开发者自行执行，AI不得擅自操作实际数据库。

### 4.4 开发过程中的问题处理

如果发现以下情况，必须暂停受影响的开发任务并向开发者反馈：

- 产品需求存在歧义或业务规则冲突。
- 技术方案存在错误或无法实施。
- 实际代码与技术契约存在明显冲突。
- 需要改变已确认的接口或数据结构。
- 需要进行删除业务代码或大范围重构。
- 存在未经确认的重大技术调整。

对于不影响既定方案的普通实现细节，AI可以自主处理，不必频繁打断开发流程。

## 五、代码质量要求

代码必须符合项目现有的编码规范，重点关注：

1. 命名规范及代码组织。
2. 模块职责及函数设计。
3. 错误处理及日志处理。
4. 请求参数校验及权限控制。
5. 数据库操作及事务处理。
6. 接口定义及响应结构。
7. 并发安全及资源管理。
8. 公共组件复用及重复代码控制。

代码应保持职责清晰、结构合理，避免过度设计和不必要的复杂度。

对于技术契约中未明确但实际实现必需的细节，AI可以提出补充建议，经开发者确认后再实施。

## 六、代码自检

开发完成后，必须进行代码自检。

### 6.1 需求符合性检查

检查：

- 是否实现产品契约中的业务需求。
- 是否正确实现已确认的业务规则。
- 是否覆盖技术契约规定的功能范围。
- 是否存在需求遗漏或错误实现。

### 6.2 技术方案符合性检查

检查：

- 是否符合后端技术契约。
- 接口及数据结构是否符合约定。
- 模块职责及调用关系是否合理。
- 数据库相关代码是否符合设计。
- 是否擅自改变已确认的技术方案。

### 6.3 代码质量检查

检查：

- 是否符合项目架构和编码规范。
- 是否存在重复实现或无关修改。
- 是否存在明显的错误处理遗漏。
- 是否存在资源管理或并发安全问题。
- 是否存在不必要的依赖和复杂度。
- 是否存在未经确认的代码删除或重大调整。

### 6.4 问题处理

发现代码问题时，优先在已确认的开发范围内直接修复。

如果问题涉及业务规则、技术方案或需要开发者决策的重大调整，必须先向开发者反馈，确认后再修改。

## 七、执行约束

1. 必须以已确认的产品契约和后端技术契约作为开发依据。
2. 必须结合实际项目代码实施开发。
3. 必须遵循项目现有架构和编码规范。
4. 优先复用已有组件，避免重复实现。
5. 不得擅自改变已确认的业务规则、接口约定及数据结构。
6. 不得擅自引入新的技术栈或第三方依赖。
7. 不得擅自修改与本次需求无关的业务代码。
8. 删除已有业务代码或进行大范围重构前，必须获得开发者确认。
9. 外部数据库操作必须交由开发者执行。
10. 不得将未经确认的业务或技术调整直接写入代码。
11. 开发过程中发现无法解决的问题，必须及时向开发者反馈。

## 八、完成标准

同时满足以下条件，才算完成：

- [ ] 已读取项目根目录下的"项目上下文.md"及两份需求契约。
- [ ] 已分析本次需求涉及的实际后端代码。
- [ ] 已明确代码修改方案及变更范围。
- [ ] 已完成后端功能代码开发。
- [ ] 已完成必要的数据库模型及相关代码变更。
- [ ] 外部数据库操作已整理为开发者可执行的操作说明。
- [ ] 代码符合项目架构及编码规范。
- [ ] 代码实现符合产品契约和后端技术契约。
- [ ] 已完成代码自检并处理发现的问题。
- [ ] 未擅自修改无关业务代码或已确认的技术方案。
- [ ] 已整理完整的代码变更报告。

完成后，向开发者说明修改文件清单、各文件变更内容、核心实现逻辑、数据库操作要求、契约符合情况及尚未解决的问题。

本Skill不以开发者额外审核确认为完成前提，完成标准满足后即可结束开发任务。
