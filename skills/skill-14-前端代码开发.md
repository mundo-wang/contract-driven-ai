# 前端代码开发

## 一、任务目标

根据本次需求的产品契约、前端技术契约、前端测试契约、后端接口文档、项目上下文及现有前端代码，完成前端功能开发。

严格遵循已确认的业务规则、技术方案和项目编码规范，合理控制代码变更范围，确保页面交互、接口调用及业务状态处理符合需求及技术设计。

本阶段只负责代码开发，不实际执行接口调用或运行项目，因此无法验证后端接口的实际返回。

## 二、执行前提

必须读取以下文件：

1. 项目根目录下的"项目上下文.md"
2. 本次需求的1.产品契约.md
3. 本次需求的2.前端技术契约.md
4. 本次需求的3.前端测试契约.md

同时获取后端接口文档（如 Swagger）。

本次需求的三份前端契约必须已经通过独立审查，并由开发者确认通过。

如果缺少必要文件、契约尚未定稿或存在影响开发的待确认事项，必须停止相关开发并向开发者反馈。

必须结合实际项目代码分析现有页面、组件、路由、状态管理、接口封装及公共组件，不能仅根据契约文字直接生成代码。

### 前置分析反问

开始执行前，AI必须先完成以下步骤：

1. **资料分析**：仔细阅读本Skill要求读取的全部资料，包括项目上下文、相关契约及实际代码，全面理解本次任务的范围、目标和约束。
2. **识别不确定点**：基于资料分析，主动识别以下类型的问题：
   - 资料之间存在矛盾、冲突或不一致的地方。
   - 契约、代码或文档中存在模糊、遗漏或无法确认的内容。
   - 本Skill的流程、标准或要求与当前项目实际情况可能存在不匹配的地方。
   - 开发者可能尚未明确说明，但对本次任务执行有实质性影响的约束、例外或特殊要求。
3. **列举并提问**：将识别出的不确定点整理为具体问题，向开发者提问。提问应聚焦影响任务正确性的关键问题，避免重复询问已经明确的信息。
4. **确认后执行**：开发者解答后，AI以解答为准开展后续工作。如经分析后不存在不确定点，可直接开始执行。

## 三、开发分析

### 3.1 理解需求与技术方案

阅读产品契约和前端技术契约，明确：

- 本次需求的业务目标及业务规则。
- 涉及的页面、组件及文件变更范围。
- 路由及导航设计。
- 交互逻辑及状态管理方案。
- 需要调用的后端接口及数据处理方式。
- 表单字段、校验规则及错误提示方式。
- 技术约束及异常处理方式。

### 3.2 分析现有代码

结合项目上下文，阅读本次需求涉及的前端实际代码，识别：

- 项目目录结构及页面组织方式。
- 组件职责及相互关系。
- 路由配置及页面跳转逻辑。
- 状态管理方案及数据流转路径。
- 接口调用封装及响应处理方式。
- 公共组件、工具函数及样式规范。
- 现有代码中的可复用实现。

优先复用项目已有的公共组件、工具函数和样式，避免重复实现。

### 3.3 制定开发方案

根据前端技术契约和实际代码，明确：

- 需要新增、修改的页面及组件文件。
- 各页面及组件承担的职责。
- 路由配置及导航调整。
- 状态管理方案的变更。
- 接口调用及数据处理实现方式。
- 表单校验及错误提示实现。
- 可能影响现有功能的修改点。

如果发现前端技术契约存在遗漏、冲突或无法落地的情况，必须向开发者说明，不得擅自改变已确认的技术方案。

对于前端技术契约未明确规定的实现细节，允许结合实际代码合理调整，但不得改变已确认的业务规则、接口约定及页面交互逻辑。

## 四、代码开发

### 4.1 开发实施

按照确认的开发方案逐步完成代码修改：

1. 根据前端技术契约新增或修改目标页面及组件。
2. 实现路由配置及页面跳转逻辑。
3. 实现状态管理及数据流转。
4. 实现接口调用及请求响应处理。
5. 实现表单校验、错误处理及用户提示。
6. 实现加载状态、空状态等页面反馈。
7. 检查代码变更是否符合前端技术契约。

开发过程中允许AI自主完成明确的开发任务，不需要每次修改都等待开发者确认。

### 4.2 代码变更管理

允许AI根据开发需要新增、修改和删除前端代码文件，但必须遵循以下要求：

- 所有变更必须属于本次需求范围。
- 优先采用局部修改，避免无关重构。
- 删除已有前端业务代码前，必须获得开发者确认。
- 进行大范围重构前，必须获得开发者确认。
- 不得擅自修改与本次需求无关的业务逻辑。
- 不得擅自引入新的技术栈或第三方依赖。

### 4.3 开发过程中的问题处理

如果发现以下情况，必须暂停受影响的开发任务并向开发者反馈：

- 产品需求存在歧义或业务规则冲突。
- 前端技术契约中的技术方案存在错误或无法实施。
- 实际代码与前端技术契约存在明显冲突。
- 需要改变已确认的接口约定或页面交互逻辑。
- 需要进行删除前端业务代码或大范围重构。
- 存在未经确认的重大技术调整。

对于不影响既定方案的普通实现细节，AI可以自主处理，不必频繁打断开发流程。

## 五、代码质量要求

代码必须符合项目现有的编码规范，重点关注：

1. 命名规范及代码组织。
2. 组件职责及页面结构设计。
3. 状态管理及数据流转。
4. 接口调用及错误处理。
5. 表单校验及用户提示。
6. 路由配置及导航逻辑。
7. 加载状态、空状态及异常反馈。
8. 公共组件复用及重复代码控制。
9. 样式规范及响应式处理。

代码应保持职责清晰、结构合理，避免过度设计和不必要的复杂度。

对于前端技术契约中未明确但实际实现必需的细节，AI可以提出补充建议，经开发者确认后再实施。

## 六、代码自检

开发完成后，必须进行代码自检。

### 6.1 需求符合性检查

检查：

- 是否实现产品契约中的业务需求。
- 是否正确实现已确认的业务规则。
- 是否覆盖前端技术契约规定的功能范围。
- 是否存在需求遗漏或错误实现。

### 6.2 技术方案符合性检查

检查：

- 是否符合前端技术契约。
- 页面及组件结构是否符合约定。
- 路由及导航设计是否合理。
- 接口调用是否与后端接口文档一致。
- 状态管理及表单校验是否符合设计。
- 是否擅自改变已确认的技术方案。

### 6.3 代码质量检查

检查：

- 是否符合项目架构和编码规范。
- 是否存在重复实现或无关修改。
- 是否存在明显的错误处理遗漏。
- 是否存在不必要的依赖和复杂度。
- 是否存在未经确认的代码删除或重大调整。

### 6.4 问题处理

发现代码问题时，优先在已确认的开发范围内直接修复。

如果问题涉及业务规则、技术方案或需要开发者决策的重大调整，必须先向开发者反馈，确认后再修改。

## 七、执行约束

1. 必须以已确认的产品契约和前端技术契约作为开发依据。
2. 必须结合实际项目代码实施开发。
3. 必须遵循项目现有架构和编码规范。
4. 优先复用已有组件，避免重复实现。
5. 不得擅自改变已确认的业务规则、接口约定及页面交互逻辑。
6. 不得擅自引入新的技术栈或第三方依赖。
7. 不得擅自修改与本次需求无关的前端业务代码。
8. 删除已有前端业务代码或进行大范围重构前，必须获得开发者确认。
9. 不得将未经确认的业务或技术调整直接写入代码。
10. 开发过程中发现无法解决的问题，必须及时向开发者反馈。
11. 本阶段不实际执行接口调用，无法验证后端接口的实际返回，接口调用实现以后端接口文档为准。

## 八、完成标准

同时满足以下条件，才算完成：

- [ ] 已读取项目根目录下的"项目上下文.md"及三份需求契约。
- [ ] 已分析本次需求涉及的实际前端代码。
- [ ] 已明确代码修改方案及变更范围。
- [ ] 已完成前端功能代码开发。
- [ ] 代码符合项目架构及编码规范。
- [ ] 代码实现符合产品契约和前端技术契约。
- [ ] 接口调用设计与后端接口文档保持一致。
- [ ] 已完成代码自检并处理发现的问题。
- [ ] 未擅自修改无关业务代码或已确认的技术方案。
- [ ] 已整理完整的代码变更报告。

完成后，通过聊天框向开发者输出代码变更报告，不要求额外生成独立报告文件。

代码变更报告应包含：修改文件清单、各文件变更内容、核心实现逻辑、契约符合情况及尚未解决的问题。

本Skill不以开发者额外审核确认为完成前提，完成标准满足后即可结束开发任务。
