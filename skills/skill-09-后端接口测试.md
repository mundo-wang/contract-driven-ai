# 后端接口自动化测试

## 一、任务目标

根据本次需求的后端测试契约、产品契约、后端技术契约、项目上下文及实际后端代码，编写并执行接口自动化测试。

验证后端接口、核心业务逻辑及数据处理是否符合契约要求，分析测试失败原因，确保测试结果准确、可追溯。

## 二、执行前提

必须读取以下文件：

1. 项目根目录下的"项目上下文.md"
2. 本次需求的1.产品契约.md
3. 本次需求的2.后端技术契约.md
4. 本次需求的3.后端测试契约.md

同时阅读本次需求涉及的实际后端代码。

本次需求的三份契约必须已经通过独立审查，并由开发者确认通过。

如果缺少必要文件、契约尚未定稿或存在影响测试执行的待确认事项，必须停止相关测试并向开发者反馈。

### 前置分析反问

开始执行前，AI必须先完成以下步骤：

1. **资料分析**：仔细阅读本Skill要求读取的全部资料，包括项目上下文、相关契约及实际代码，全面理解本次任务的范围、目标和约束。
2. **识别不确定点**：基于资料分析，主动识别以下类型的问题：
   - 资料之间存在矛盾、冲突或不一致的地方。
   - 契约、代码或文档中存在模糊、遗漏或无法确认的内容。
   - 本Skill的流程、标准或要求与当前项目实际情况可能存在不匹配的地方。
   - 开发者可能尚未明确说明，但对本次任务执行有实质性影响的约束、例外或特殊要求。
3. **列举并提问**：将识别出的不确定点整理为具体问题，向开发者提问。提问应聚焦影响任务正确性的关键问题，避免重复询问已经明确的信息。
4. **确认后执行**：开发者解答后，AI以解答为准开展后续工作。如经分析后不存在不确定点，可直接开始执行。

## 三、测试分析

### 3.1 理解测试契约

阅读三份需求契约，明确：

- 本次需求的业务规则及验收标准。
- 后端接口及核心业务逻辑。
- 测试范围及测试策略。
- 测试用例及预期结果。
- 测试数据及数据库验证要求。
- 特殊场景及技术约束。

### 3.2 分析实际代码

结合项目现有代码，识别：

- 接口路由及请求处理方式。
- 请求参数及响应结构。
- 核心业务逻辑及调用链路。
- 身份认证及权限控制。
- 数据库访问及事务处理。
- 现有测试框架及公共测试组件。

测试实现必须符合实际代码结构，优先复用项目已有测试工具和组件，不得擅自引入新的测试依赖。

### 3.3 建立测试对应关系

测试用例必须与后端测试契约逐项对应，并能够追溯到具体契约用例。

重点覆盖：

- 正常业务流程。
- 异常业务流程。
- 边界条件。
- 请求参数校验。
- 身份认证及权限校验。
- 数据库读写及持久化验证。
- 幂等性及并发场景（业务需要时）。

不得擅自缩减测试契约规定的测试范围。

## 四、自动化测试开发

### 4.1 测试代码编写

根据后端测试契约编写自动化测试代码：

1. 优先使用项目现有测试框架。
2. 按照测试契约组织测试用例。
3. 为每个测试用例明确测试输入和操作步骤。
4. 验证接口响应及业务处理结果。
5. 验证必要的数据库数据变化。
6. 验证异常场景及边界条件。
7. 确保测试结果能够客观判断是否通过。

测试代码必须符合项目编码规范，并保持结构清晰、职责明确。

### 4.2 测试代码管理

允许AI直接新增、修改和删除测试代码。

执行时遵循以下要求：

- 测试代码变更必须属于本次需求范围。
- 优先复用现有测试组件。
- 不得擅自修改无关测试代码。
- 删除已有测试代码前必须获得开发者确认。
- 不得通过修改测试预期结果的方式掩盖业务缺陷。
- 不得擅自改变后端测试契约规定的测试要求。

### 4.3 数据库访问与测试数据管理

在必要时，允许AI Agent直接连接项目数据库，根据本次测试需要，对涉及的数据表执行查询及测试数据管理操作。

数据库访问权限包括：

- 查询：允许查询本次测试涉及的数据表及相关数据。
- 新增：允许创建本次测试所需的数据。
- 修改：只允许修改本次测试自行创建的数据。
- 删除：只允许删除本次测试自行创建的数据。

执行时必须遵循以下要求：

1. 数据库操作必须限定在本次需求涉及的数据表和测试范围内。
2. 允许查询测试所需的已有数据，但不得修改或删除测试开始前已经存在的数据。
3. 允许新增本次测试专用的数据，并记录新增数据的标识及归属关系。
4. 只允许修改、删除本次测试自行新增的数据，不得操作其他已有业务数据。
5. 不得因测试数据与已有数据存在关联，就擅自修改或删除已有数据。
6. 测试结束后，应清理本次测试自行新增且不再需要的数据。
7. 如果无法确认某条数据是否由本次测试创建，不得修改或删除，应向开发者反馈。
8. 数据库连接信息及访问权限必须来自开发者提供的合法配置，不得自行猜测或获取。
9. 不得擅自修改数据库表结构、字段、索引、约束或执行其他数据库结构变更。
10. 不得访问或修改与本次测试无关的数据表。

数据库数据级操作由AI在上述授权范围内自主执行，不需要每次操作都向开发者确认。

### 4.4 外部依赖准备

如果测试依赖的数据库表、外部服务或其他资源尚未准备好，应向开发者说明：

- 缺少的外部资源。
- 具体依赖内容。
- 需要开发者执行的准备操作。
- 相关操作说明或必要的SQL语句。

涉及创建数据表、修改表结构、创建索引及其他外部资源变更时，必须由开发者执行，AI不得擅自操作。

## 五、测试执行

### 5.1 执行自动化测试

允许AI直接执行接口自动化测试，包括：

- 执行必要的测试命令。
- 启动测试所需的依赖。
- 执行指定测试用例。
- 执行完整测试集。
- 读取和分析测试结果。

测试执行必须以实际运行结果为依据，不得根据代码推测测试通过。

### 5.2 测试失败分析

测试失败时，必须分析失败原因，并区分以下情况：

1. 业务代码缺陷：后端实现不符合契约要求。
2. 测试代码缺陷：测试逻辑、断言或执行方式存在问题。
3. 测试数据问题：测试数据不满足用例前置条件或数据状态不正确。
4. 外部依赖问题：数据库或其他依赖资源不可用、配置不正确。
5. 契约不一致：测试契约与实际技术设计或业务要求存在冲突。

不得将所有测试失败简单归类为业务代码问题。

### 5.3 失败处理

根据失败原因采取不同处理方式：

- 测试代码缺陷：允许AI直接修复测试代码。
- 测试数据问题：允许AI在本次测试数据操作权限范围内修复。
- 外部依赖问题：向开发者说明原因及处理要求。
- 业务代码缺陷：分析具体问题并提供修复建议，不得直接修改后端业务代码。
- 契约问题：暂停受影响的测试，向开发者反馈，确认后再继续。

### 5.4 重新执行测试

修复测试代码或测试数据后，必须重新执行相关测试。

必要时重新执行完整测试集，确认修改没有引入新的测试问题。

不得仅根据修改结果宣称测试通过，必须以实际执行结果为准。

## 六、测试结果报告

测试完成后，通过聊天框向开发者输出完整测试报告，不要求额外生成独立报告文件。

### 6.1 测试概况

说明：

- 本次测试范围。
- 测试用例总数。
- 测试通过数量。
- 测试失败数量。
- 未执行数量。
- 最终测试结论。

### 6.2 测试结果明细

说明各测试用例的执行结果，明确哪些通过、哪些失败、哪些未执行。

### 6.3 失败问题分析

每个失败问题必须提供：

- 对应的契约用例。
- 测试文件及测试函数。
- 接口路径。
- 实际错误信息。
- 失败原因及分析结论。
- 相关代码位置。
- 建议处理方式。

不得只提供笼统的失败描述，必须提供开发者能够定位问题的信息。

### 6.4 遗留问题

列出尚未解决的问题，包括业务代码缺陷、测试契约问题、外部依赖问题及未完成的测试项。

### 6.5 最终测试结论

根据实际执行结果明确说明：

- 测试是否全部通过。
- 是否存在未解决的失败用例。
- 是否存在未执行的测试项。
- 是否满足本次测试契约要求。

## 七、执行约束

1. 必须以已确认的三份需求契约作为测试依据。
2. 必须结合实际后端代码编写测试。
3. 必须逐项对应后端测试契约中的测试用例。
4. 不得擅自缩减测试范围或改变预期结果。
5. 不得擅自引入新的测试依赖。
6. 不得擅自修改后端业务代码。
7. 删除已有测试代码前必须获得开发者确认。
8. 不得修改或删除本次测试开始前已经存在的数据库数据。
9. 只允许新增、修改和删除本次测试自行创建的数据。
10. 不得擅自执行数据库结构变更或其他外部资源变更。
11. 测试失败必须分析具体原因，不得掩盖或忽略。
12. 所有测试结论必须以实际执行结果为依据。
13. 测试报告必须通过聊天框反馈给开发者。

- [ ] 已读取项目根目录下的"项目上下文.md"及三份需求契约。
- [ ] 已分析本次需求涉及的实际后端代码。
- [ ] 已明确测试范围及测试用例对应关系。
- [ ] 已完成自动化测试代码编写。
- [ ] 测试用例与后端测试契约逐项对应。
- [ ] 已完成测试数据准备及必要的数据验证。
- [ ] 已按需执行数据库查询及测试数据管理。
- [ ] 未修改或删除本次测试开始前已经存在的数据库数据。
- [ ] 已执行自动化测试并获取实际结果。
- [ ] 所有失败用例均已完成原因分析。
- [ ] 测试代码问题已修复并重新执行。
- [ ] 业务代码缺陷及契约问题已明确反馈。
- [ ] 未擅自修改后端业务代码或执行未经授权的外部操作。
- [ ] 已通过聊天框输出完整测试报告。
- [ ] 所有测试项均已执行，或未执行原因已明确说明。

完成上述工作后，即可结束本次测试任务，不要求开发者额外审核确认。
